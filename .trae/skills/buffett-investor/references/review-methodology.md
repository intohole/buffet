# Review Methodology - 通用复盘方法论

复盘不是生成文档，而是从决策中提炼可复用模式。本方法论与具体项目数据解耦，复盘数据写入工作区，不写入技能目录。

## 复盘核心原则

1. **双向记录**：记录"追涨亏钱"时必须同时评估"如果等回调而踏空，成本是多少"
2. **模式提炼**：从单次事件提炼可复用决策模式，而非记录流水账
3. **置信度分级**：高(≥2次验证)→可写入硬约束；中(1次)→参考；低→待验证
4. **来源标注**：每条经验必须标注验证来源（搜索关键词/URL）

## 复盘5步流程

### Step 1: 事实还原
- 本次分析的核心标的/板块
- 关键判断依据（数据点+逻辑链）
- 实际市场表现（T+1/T+5/T+20）
- 判断正确/错误/部分正确

### Step 2: 归因分析
- 正确判断：哪些信号有效？是否可复用？
- 错误判断：哪个环节失效？数据问题/逻辑问题/情绪干扰？
- 关键转折点：什么信号标志着趋势变化？

### Step 3: 踏空成本对等评估
- 若建议"等回调/观望/回避"：
  - 踏空成本 = (期间涨幅) × 计划仓位 × 持仓周期
  - 若踏空成本>潜在回调损失，则"等回调"策略净负收益
- 若建议"追涨买入"：
  - 追涨损失 = (买入价-止损价) × 仓位
  - 评估追涨是否值得

### Step 4: 模式提炼
从本次事件提炼可复用模式：
```
### [日期] [场景描述]
- 情境：什么情况下遇到的
- 信号：哪些领先信号出现/未出现
- 问题：技能输出哪里不对
- 原因：为什么会出问题
- 修正：应该怎么做
- 规则提炼：[可复用原则]
- 验证来源：[搜索关键词或URL]
- 置信度：高/中/低
```

### Step 5: 经验沉淀路径

| 置信度 | 沉淀路径 | 使用方式 |
|--------|---------|---------|
| 高（≥2次验证） | 提炼为通用规则→[hard-constraints.md](hard-constraints.md) | 写入硬约束，违反即预警 |
| 中（1次验证） | 记录到工作区经验文件 | 分析时检索评估 |
| 低（待验证） | 仅记录，标注"待验证" | 不作为决策依据 |

## 工作区数据约定（可选，不强制）

技能不依赖任何项目特定数据。若用户希望启用个性化能力，可在工作区创建以下目录：

| 工作区目录 | 用途 | 内容 |
|-----------|------|------|
| `${WORKSPACE_DIR}/.investor-context/` | 用户上下文 | user-portfolio.md(持仓)/user-profile.md(风格)/trade-history.md(操作日志) |
| `${WORKSPACE_DIR}/.investor-experience/` | 经验库 | 按分类组织的经验文件 |
| `${WORKSPACE_DIR}/.investor-reviews/` | 复盘文档 | review-YYYYMMDD-HHmm.md |

**优雅降级规则**：
- 工作区无`.investor-context/`→跳过用户上下文加载，不输出个性化建议
- 工作区无`.investor-experience/`→跳过经验检索，仅用硬约束
- 工作区无`.investor-reviews/`→复盘文档由用户自行保存

## 经验分类索引（通用模式库）

经验按决策类型分类，每类提炼通用模式：

| 分类 | 模式类型 | 示例 |
|------|---------|------|
| 择时类 | 等回调vs追涨的双向成本评估 | 涨停潮后不追高，等回调至MA20 |
| 选股类 | 财务排雷+业绩质量验证 | 扣非/归母<50%淘汰 |
| 风控类 | 仓位/止损/板块集中度 | 距止损位<3%减仓50% |
| 情绪类 | 市场情绪周期定位 | 涨停潮次日必分化 |
| 产业类 | 产业链传导+渗透率定位 | 渗透率10-50%成长期重仓 |
